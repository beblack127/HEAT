## 2. 현재 상태 점검

중간발표 숫자의 출처: HEAT `reports/gt_midterm/10_실험_출처별_정리.md` (4개 예측 시점 2024-10-27, 2025-01-26, 2025-04-27, 2025-07-27, 13주 앞, 416개 동, WAPE).

### 2.1 근거가 단단한 것

| 주장 | 근거 |
|---|---|
| 대표 모델이 기준선보다 낫다 | 작년 같은 주 + ARIMA·푸리에 1:1 결합 11.8% vs 작년 같은 주 21.6% (보정 13.9%). 동·시점의 64%에서 더 정확 |
| 2024-08~10은 자료 오류다 | 생활이동만 작년 대비 최대 1.69배(월 단위). 같은 기간 생활인구 0.96~1.00, 지하철 하차 0.98~1.04, 카드 매출(음식업, 분기) 0.97. 출근·귀가 목적 이동도 같이 뛰었다 → `figures/anomaly_appendix.png` |
| 핫플은 20~39세 비중이 높다 | 방문객 중 20~39세: 서교동 61%, 방문량 상위 10% 동 중앙값 40%, 서울 동 중앙값 28.5% (2025). 상위 10%는 전 연령 방문량으로 뽑았으므로 순환 논리가 아니다 → `figures/age_share_appendix.png` |
| 다른 출처에서도 같은 연령 패턴 | 카드 매출 중 20~39세 비중: 방문량 상위 10% 동 30.6% vs 중앙값 21.2%, 서교동 58%. 두 출처의 동별 20~39세 비중 순위 상관 0.69 (396개 동) |
| 20~39세 선택의 선행연구 | 김경선·김동섭(2019) 한국콘텐츠학회논문지 19(2): 40세 이하 매출 비중·40세 미만 유동인구 비율이 상업 젠트리피케이션과 관련. 강현모·이상경(2019) 한국측량학회지 37(6): 20~30대는 매출액보다 상권 성장에 더 큰 영향 (초록 기준 확인) |

### 2.2 약점 (최종 전에 해결하거나, 솔직하게 말할 것)

| 약점 | 내용 | 대응 |
|---|---|---|
| 같은 시점으로 고르고 보고 | 4개 시점으로 모델과 보정을 고르고 그 성능을 보고했다 | 지금 숫자는 검증(validation) 결과로 부른다. 모든 선택을 고정·커밋한 뒤 2026년 구간으로 최종 시험 한 번 (HEAT F12) |
| 시점 4개 | 시점 하나가 평균을 크게 바꾼다 | 2024-07~2025-07 매월 13개 시점으로 확대 계획. 2024-07~10 시점은 이상 구간과 겹치므로 처리 규칙을 먼저 정한다 |
| 4+5+7은 사실상 '기타' | 2025년 4+5+7 이동 중 기타 98.7%, 쇼핑 1.2%, 관광 0.2% | 숨기지 말고 먼저 말한다. 기타에 들어갈 이동 예시 → `figures/other_purpose_{ko,en}.png`. 데이터 정의서로 분류 기준 확인 |
| 20~39세가 "더 낫다"는 증명 없음 | 20~39세 방문량과 카드 매출 순위 상관 0.636, 전 연령 0.639로 같다 | "설계상 선택"이라고 말한다. 최종 전에 전 연령 정답과 떠오르는 곳 적중률을 비교 |
| 방문 증가 ≠ 매출 증가 | 2024→2025 상반기 동별 방문 증가율과 카드 매출 증가율의 상관이 연령과 상관없이 0 근처 (396개 동) | "떠오르는 곳"과 "이유" 설명을 만들기 전에 무엇을 뜬다고 볼지 다시 점검 (HEAT F1, F11) |
| 떠오르는 곳 판정이 약하다 | 상위 10% 적중률 모델 58%, 지속(지금 그대로) 53%, 무작위 10%. 현재 핫스팟은 모든 방법이 약 95% | 최종 발표의 핵심 과제. 급변 대응(행사·이상치 처리)과 입력 개선 |
| 검색량 효과가 불분명 | 검색을 넣으면 4시점 평균 오차가 늘었다. 가짜 입력(다른 동 검색)과 결과가 거의 같다 (23.6% vs 23.7%) | 검색 설정(척도, 시차, 붙이는 규칙) 재조정. 선행성 검정(교차상관, 그랜저) |

### 2.3 Q&A 자료에서 고친 숫자

- "핫플 방문객의 20~39세 비중 50~60%" → 50~60%는 서교동·역삼1동뿐이다. 상위 10% 중앙값 40%로 고쳤다.
- "생활인구는 독립 자료" → 생활인구는 생활이동과 같은 통신 원자료다. "independent"를 뺐다.
- Word Q&A의 "핫플 예측은 아직 검증 안 됨" → 떠오르는 곳 적중률(58% vs 53%)이 이미 있다. 쓸지 팀이 정한다.

## 3. 최종 발표까지 할 일

HEAT README §4.2의 F1~F13 계획에 중간발표 이후 나온 아이디어를 더했다.

### 3.1 먼저 할 일 (첫 회의에서 정하기)

1. **예측 결과 표 형식 확정.** HEAT README에 정한 형식을 모든 실험이 따른다.
   ```
   dong_code8, origin_week, target_week, model, y_hat, share_hat, is_hot, is_emerging
   ```
   모델·피처 담당은 이 표만 내고, 시스템은 이 표만 읽는다. 서로 기다리지 않고 따로 작업할 수 있다.
2. **역할 이름 배정.** 잠정안: 시스템 김재현(계속), 모델링 1명, 피처 발굴·실험 2명.
3. **최종 시험 규칙 고정.** 2026년 구간은 모든 선택을 커밋한 뒤 한 번만 연다.

### 3.2 모델과 입력

| 할 일 | 내용 | 관련 계획 |
|---|---|---|
| 예정된 행사를 입력으로 | 서울시 행사 모음 사이트에서 예측 구간의 행사를 모은다. 행사가 있다고 무조건 넣지 않고, 작년 비슷한 행사 때 실제로 튄 비율(피크 비율)을 반영한다 | F3 |
| 급변 구간 처리 | 작년 하루 피크(이상치 수준)를 행사 후보로 표시하고, 표시·윈저라이징·스무딩을 넣고 뺀 결과를 비교한다. 중간발표의 "extreme changes" 상당수가 행사 피크일 가능성 | F3 |
| 검색량 재조정 | 서울 대비 비중, 시차 1·2·3개월, 필요하면 주 단위 재수집. 효과가 시점마다 안정적인지 확인 | F6, F8 |
| 다른 외부 요인 | 카드 매출(재현이 받아 둔 자료, 상권분석서비스 추정매출 2023~2025는 `data/reference/`에 있음), 버스, 주 단위 점포 피처. 교수님 피드백 1번 | F7, F11 |
| 일 단위 피처 | 요일·명절·행사일 등 일 단위 정보를 주 단위 피처로 정리 | F7 |
| 확장 모델 | 여러 동을 함께 학습하는 Ridge·LightGBM. 성능 차이가 작으면 입력을 넣는 모델 쪽으로 간다 | F9 |
| 20~39세 vs 전 연령 | 같은 모델에 전 연령 4+5+7을 정답으로 넣고 떠오르는 곳 적중률 비교 | F1 |

**주의: 미래 정보 누수.** 행사 입력은 예측 시점에 이미 공개된 일정만 쓴다. 실제 방문 결과를 보고 고른 행사를 넣으면 안 된다.

### 3.3 시스템 (프로토타입)

현재 구조: `maps/HEAT_system.html` 한 파일(4.7MB)에 지도와 자료가 들어 있다. `src/gt/07_map_data.py`가 `hot_map.json`(주별 실제값, 4시점 예측, WAPE, 마지막 주 이후 13주 실시간 예측)을 만들고, `src/gt/14_hot_html.py`가 원본 템플릿 `src/nametags/app_v4.html`을 문자열 치환으로 고쳐 핫플지수 화면을 만든다.

| 할 일 | 내용 |
|---|---|
| 실험 비교 화면 | 표준 예측 표를 읽어 모델을 골라 동별로 비교. 모델별 동 WAPE를 지도 색으로 칠해 오류 분석에 쓴다 |
| "왜"를 보여 주는 근거 패널 | 이미 만든 검색량·개폐업 탭(지금은 숨김)을 동 상세 화면의 근거로 다시 붙인다. 교수님 피드백 2번 |
| 행사 표시 | 예측 구간의 예정 행사를 지도 마커와 그래프에 표시. 작년 피크 주에 "작년 이때 ○○ 행사" 표시 |
| 뉴스 근거 | 네이버 뉴스 API로 해당 동·시기 기사를 찾아 요인과 링크를 보여 준다. 정적 HTML에 API 키를 넣으면 공개되므로, **빌드할 때 미리 검색해 결과만 저장**한다. 기사에서 행사·개업·방송 노출 같은 유형을 뽑으면 입력 피처로도 쓸 수 있다 |
| 배포 | 서버가 필요 없는 정적 파일이고 저장소가 공개라서 GitHub Pages로 바로 배포할 수 있다. 이후 GitHub Actions로 자료 갱신 → 예측 → 재빌드 → 배포를 주기적으로 돌릴 수 있다 |

기술적 주의점:
- `14_hot_html.py`는 템플릿 문구를 찾아 바꾸는 방식이라, 템플릿을 조금만 고쳐도 `assert`에서 멈춘다. 탭을 계속 늘릴 거라면 템플릿을 직접 고치는 쪽이 낫다.
- 모델·근거·뉴스가 더해지면 파일이 커진다. 배포할 때는 자료를 별도 JSON으로 빼서 필요할 때 불러오는 구조가 좋다.

## 5. 다시 만들기

`<codex_root>`는 HEAT 작업 폴더의 상위(생활이동 월별 CSV가 있는 곳)다.

```bash
python scripts/build_anomaly_figure.py <codex_root> <HEAT v3_seoul_quarterly.csv> figures
python scripts/build_age_share_figure.py <codex_root> figures
python scripts/build_other_figure.py figures
python scripts/age_evidence.py <codex_root>
```

- `build_anomaly_figure.py`: 서울 전체 월별 작년 대비 비율 (생활이동 목적별, 생활인구, 지하철, 카드 매출). 카드 매출은 HEAT `reports/gt_midterm/tables/v3_seoul_quarterly.csv`
- `build_age_share_figure.py`: 2025년 동별 20~39세 방문 비중
- `build_other_figure.py`: '기타' 목적 예시 표 (예시이며 공식 분류 아님)
- `age_evidence.py`: 상권분석서비스 추정매출을 상권 → 행정동으로 붙여 연령별 방문과 카드 매출을 비교 (수준, 증가율, 연령 구성). 결과는 2.1~2.2절 숫자
- PNG는 SVG를 브라우저(헤드리스 Edge)로 렌더링했다.
