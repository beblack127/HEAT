## 0. 한 줄 요약

2022~2025년 자료로 학습해 2026년의 **행정동별 검색량**과 **행정동별 음식점 개업·폐업**을 3개월 앞서 예측한다. 단순 기준선(naive, 계절 naive)을 넘는지, 어떤 모델과 외생변수가 도움이 되는지 확인한다.

## 2. 검증 구조

| fold | 학습 | 평가 origin (h = 3) | 실제값 구간 |
|---|---|---|---|
| F2024 | 2022-01~2023-12 | 2023-12 ~ 2024-09 (10개) | 2024-01~12 |
| F2025 | 2022-01~2024-12 | 2024-12 ~ 2025-09 (10개) | 2025-01~12 |
| 최종 | 2022-01~2025-12 | 2025-12 ~ 2026-06 (7개) | 2026-01~09 |

- origin t에서 t+1 ~ t+h를 예측한다. 실제값 구간이 그 fold의 시험 연도 안에 들어오는 origin만 쓴다.
- **h = 6**: F2024 origin 2023-12~2024-06, F2025 2024-12~2025-06, 최종 2025-12~2026-03.
- **h = 12**: F2024·F2025에서 origin 하나씩(전년 12월). 최종 시험은 실제값이 9개월뿐이라 **예측만 저장하고 평가하지 않는다.**
- 모델 구조·하이퍼파라미터는 fold 학습 구간에서만 정한다. 시험 연도 안에서는 origin마다 t까지의 자료로 다시 적합하되(국소 모델), 전역 모델은 fold당 한 번 학습하고 origin마다 입력만 갱신한다 (기본값. 시간이 남으면 origin마다 재학습을 민감도로 본다).
- 전역 모델의 학습 표본은 실제값(t+1 ~ t+h)이 학습 구간 끝을 넘지 않는 origin까지만 쓴다.
- 2026-10은 부분 월(개폐업)이자 검색량 마지막 달이다. 최종 시험에 넣지 않는다.

## 3. 예측 대상

### 3.1 검색량

- 입력: `data/processed/search/행정동_검색지수_월별.csv` (행정동 × 칸 × 월, 2022-01~2026-10)
- 주 대상: 칸 `전체`의 **서울 대비 비중**(`seoul_share`). 서울 전체 검색량이 2025년 하반기부터 줄어 절대 지수 대신 비중을 쓴다.
- h = 3의 예측값: 향후 3개월 평균 비중. 보조로 최근 3개월 대비 변화(`chg_3m`과 같은 정의)도 함께 보고한다.
- 보조 칸: 동네·역·상권 칸별 비중 (탐색적).
- 지수가 있는 동: 422 / 427.

### 3.2 개폐업

주 대상 (향후 3개월 합, 행정동별)

| 대상 | 정의 |
|---|---|
| 개업 수 | ΣO(t+1..t+3) |
| 폐업 수 | ΣC(t+1..t+3) |
| 순증률 | Σ(O − C)(t+1..t+3) / S_t |

보조 대상

| 대상 | 정의 |
|---|---|
| 회전율 | Σ(O + C)(t+1..t+3) / S_t |
| 점포수 증가율 | S_{t+3} / S_t − 1 |
| 독립카페 진입률 | Σ 독립카페 개업(t+1..t+3) / S^cafe_t |
| 프랜차이즈 비중 | S^fr_{t+3} / S_{t+3} (카페·외식) |

- O, C, S의 정의, 업종 포함·제외, 프랜차이즈 판별은 `feature_spec.md` §0·§1·§3을 따른다.
- 일반음식점과 휴게음식점(매핑표 `include == 1` 업종)을 합쳐 센다 (기본값).
- 집계 수준: 서울 전체, 구(25), 행정동. 행정동이 주 수준이다.
- 피처 계산에 필요한 과거 값(12개월 누적, 영업 점포 수)은 2021년 이전 기록을 써도 된다. t 시점에 알 수 있던 정보이기 때문이다. 학습 표본(origin)은 2022-01부터.

### 3.3 개폐업 기본 점검 (모델링 전에)

- **일괄 폐업**: `bulk_closure` 플래그(같은 동·같은 폐업일 건수가 그 동 일평균의 10배 이상이면서 10건 이상). 유지(`v_keep`)·제외(`v_drop`) 두 패널로 모두 돌린다. 기본 보고는 `v_drop`, `v_keep`을 함께 적는다.
- **폐업 신고 지연**: 폐업일과 기록 수정일(`최종수정일자`·`데이터갱신일자`)의 차이 분포를 본다. 최근 달의 폐업이 덜 잡혀 있으면(지연 때문에 마지막 몇 달이 낮게 보이면) 그 달 수와 영향을 `reports/`에 남기고, 최종 시험 실제값을 언제 다시 받아야 하는지 적는다.
- **코로나 더미**: `covid = 1` (2022-01~04), 나머지 0. 모든 모델에 넣을 수 있는 외생변수로 둔다.

## 4. 모델

| 단계 | 모델 | 적용 | 구현 |
|---|---|---|---|
| 기준선 | Naive (최근 h개월 값 유지), Seasonal Naive (1년 전 같은 h개월) | 전부 | pandas |
| 국소 | ETS (AutoETS, 계절 12) | 전부 | statsforecast |
| 국소 | ARIMA / SARIMA (AutoARIMA, 계절 12) | 아래 범위 | statsforecast |
| 국소 | Theta (AutoTheta) | 전부 | statsforecast |
| 국소 | Croston / TSB | 0이 많은 개폐업 동 | statsforecast |
| 국소 + 외생 | SARIMAX | 아래 범위 | statsmodels |
| 전역 (주력) | LightGBM — 개수 대상은 Poisson 목적함수 | 전부 | lightgbm |
| 전역 (선형 기준) | Ridge — LightGBM과 같은 피처 | 전부 | scikit-learn |

**SARIMA·SARIMAX 적용 범위** (동별 계절 ARIMA는 0이 많거나 짧은 계열에서 불안정하기 때문)
- 검색량: 모든 동
- 개폐업: 서울 전체, 25개 구, 개폐업이 많은 동 (기본값: 학습 구간 월평균 개업 + 폐업 ≥ 10건)

**SARIMAX 외생변수**: 코로나 더미, 다른 데이터의 시차 값(검색 모델에는 개폐업, 개폐업 모델에는 검색량), 일괄 폐업 플래그(`v_keep`일 때). 미래 값이 필요한 외생변수는 **시차 ≥ h**로만 넣는다. origin t에서 t+1 ~ t+h를 예측할 때 이미 알려진 값이어야 하기 때문이다. 코로나 더미처럼 미래가 정해진 변수는 시차 없이 쓴다.

**Croston/TSB 적용 기준** (기본값): 학습 구간에서 개업 또는 폐업이 0인 달이 30% 이상인 동.

**전역 모델 피처** (origin t까지 알 수 있는 값만)
- 대상 자신의 시차·이동평균 (1, 2, 3, 6, 12개월), 계절(달) 변수, 코로나 더미
- 검색량: `seoul_share`, `chg_1m`, `chg_3m`, `chg_3m_sa`, `chg_12m` (계절 계수는 fold마다 다시 계산, §6)
- F&B 지표: `feature_spec.md` G1~G3 (순증률, 회전율, 업력, 업종 구성 등)
- 구 고정효과, 동 수준(학습 구간 평균)
- 검색 모델과 개폐업 모델은 서로의 값을 피처로 쓸 수 있다. 어느 쪽이 도움이 되는지는 같은 모델에서 피처 그룹만 바꿔 비교한다.

**LightGBM 시작 설정**: `num_leaves=15, min_data_in_leaf=50, learning_rate=0.03, feature_fraction=0.8, bagging_fraction=0.8, bagging_freq=1, lambda_l2=1.0, n_estimators=2000`, early stopping은 학습 구간 마지막 3개월. 개수 대상은 `objective="poisson"`, 비율·비중 대상은 L2(또는 Huber). 시드 42.

## 5. 평가

| 지표 | 대상 | 정의 |
|---|---|---|
| MASE | 전부 | 분모 = 학습 구간에서 계절 naive(1년 전 같은 h개월)의 MAE. MASE < 1이면 계절 naive보다 낫다 |
| Poisson deviance | 개업 수, 폐업 수 | 평균 Poisson deviance |
| top-K 적중률 | 동 순위 | 예측 상위 K개 동 중 실제 상위 K개에 든 비율, K = 10, 20, 30. 검색 비중 변화, 개업 수, 순증률 |
| DM 검정 | 모델 비교 | Diebold-Mariano, HAC 시차 h − 1, Harvey-Leybourne-Newbold 소표본 보정, 자유도 n − 1 t분포 |

- 결과는 fold별(F2024, F2025)로 따로 보고하고 평균만으로 결론 내리지 않는다.
- 모든 모델을 Naive·Seasonal Naive와 비교한다. 기준선을 못 넘으면 그대로 보고한다.
- Ridge ≈ LightGBM이면 단순한 Ridge를 주 모델로 보고하는 것이 낫다.
- 집계 수준별(서울·구·동) 성능을 함께 보고한다.

## 6. 누수 방지

- origin t의 입력은 t월 말까지 알 수 있던 값만.
- **검색량 계절 계수**: 현재 CSV의 `seasonal_factor`·`chg_3m_sa`는 2022~2024년으로 계산돼 있어 **F2024 fold에서는 시험 연도가 섞인다.** 모델링에서는 fold마다 학습 구간 자료로 계절 계수를 다시 계산한다 (F2024: 2022~2023, F2025: 2022~2024, 최종: 2022~2025).
- 검색어 제외 규칙은 2022년 자료만 써서 모든 fold에서 안전하다. 제외 목록(`일반어_타지명_뿌리.txt`)은 모델 결과를 본 뒤 바꾸지 않는다.
- 표준화, EB 사전분포, 하이퍼파라미터, 범주 경계값은 fold 학습 구간에서만 정한다.
- 무작위 K-fold는 쓰지 않는다.
- 최종 시험(2026-01~09)은 모든 선택을 고정한 뒤 한 번만 실행하고, 실행 전 커밋 해시를 기록한다.

## 8. 진행 순서 (Claude Code에 그대로 요청할 단위)

1. "`forecast_plan.md`대로 `src/forecast/config.py`와 `00_targets.py`를 만들어줘. 검색 대상은 fold마다 계절 계수를 다시 계산하고, 개폐업 대상은 `data/interim/음식점_개폐업사건.csv`에서 행정동 × 월로 만들어줘."
2. "`01_checks.py`로 일괄 폐업과 폐업 신고 지연을 점검하고 보고서를 써줘."
3. "기준선과 국소 모델(ETS, SARIMA, Theta, Croston/TSB)을 F2024·F2025에서 h = 3, 6, 12로 돌려줘."
4. "SARIMAX를 적용 범위에서 돌려줘. 외생변수는 시차 ≥ h."

6. "MASE, Poisson deviance, top-K, DM-HLN으로 fold별 결과 표와 그림을 만들어줘."
7. "모든 선택을 고정하고 커밋한 뒤, 최종 시험 2026-01~09를 한 번 실행해줘."
