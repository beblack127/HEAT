  - 중간발표 초안에 보인 열: `etl_ymd`, `move_purpose`, `purpose_label`, `male_20_cnt`, `feml_20_cnt`, `male_30_cnt`, `feml_30_cnt`. 도착 행정동 코드 열 이름은 파일을 열어 확인한다.

### 3.2 계산

1. 서울 도착만 남긴다 (행정동 코드 앞 두 자리 `11`).
2. 목적 4, 5, 7만 남기고, 20대·30대 남녀를 더한다 → 동 × 일 값.
3. 주(월~일)로 묶어 **유효 관측 일수로 나눈 일평균**을 `y`로 한다. 유효 일수가 7일 미만인 주는 `n_days`로 기록하고, 4일 미만이면 결측으로 둔다.
4. 동 코드를 427동으로 맞춘다 (§3.3).
5. **서울 합계** `seoul_y` = 같은 주 모든 서울 동의 `y` 합 (427동으로 맞추기 전, 원자료의 모든 서울 동 기준).
6. `share = y / seoul_y`.
7. 민감도용으로 목적 4+5만, 전 연령 버전도 같은 방식으로 만든다 (`y_p45`, `y_allage`).

출력: `data/interim/gt/target_weekly.parquet` — `dong_code8, week_end, y, share, seoul_y, n_days, y_p45, y_allage`

## 4. 입력 만들기 (`01_features.py`)

**누수 규칙 (가장 중요)**: 각 주 t의 입력값은 t보다 충분히 이전의 값이어야 하고, 예측하는 13주 모두에서 **예측 시점에 이미 알려진 값**이어야 한다. 그래서 고정 시차를 쓴다.

| 입력 | 원자료 | 주 t에 붙이는 값 | 시차 규칙 |
|---|---|---|---|
| `search_share` | `data/processed/search/행정동_검색지수_월별.csv`, 칸 `전체`, 열 `seoul_share` | **t가 속한 달 − 4개월** 의 값. 로그 변환 `log(share × 1e4)` | 월 단위 4개월 전이면 13주 앞까지 모두 이미 아는 값 |
| `fnb_stock_chg12` | `data/processed/fnb/행정동_개폐업_월별.csv`, `level == "dong"`, 열 `영업점포` | (그 달 영업점포 ÷ 12개월 전 − 1), **t가 속한 달 − 4개월** 의 값 | 신고 지연 5주도 함께 만족 |
| `subway_exit_4w` | 지하철 일별 하차 (§4.1) | 동 하차의 **4주 평균**, **t − 13주** 시점의 값. `log1p` 변환 | 13주 시차 |
| `living_pop` | 생활인구 (§4.2) | 주간(11~21시) 주 평균, **t − 13주** 시점의 값. `log1p` 변환 | 13주 시차 |
| `holiday_days` | Python `holidays` 패키지 (`holidays.KR`) | 주 t 안의 공휴일 수 (설·추석 포함) | 미래 날짜가 정해져 있어 시차 없음 |
| `y_lag52` (M3) | 정답 | `y` of t − 52주. `log1p` 변환 | 13주 앞이라도 39주 이상 과거 |

- 모든 입력은 **학습 구간 평균·표준편차로 표준화**한다 (시점마다 따로).
- 고정 시차 대신 "예측 시점에 아는 마지막 값을 13주 동안 고정"하는 방식도 있다. 이번에는 고정 시차만 쓰고, 리포트에 이 선택을 한 줄로 적는다.

### 4.1 지하철

- 출처: [서울시 지하철호선별 역별 승하차 인원 정보, OA-12914](https://data.seoul.go.kr/dataList/OA-12914/S/1/datasetView.do). 일 단위, 2023-01~2026-10 월별 파일 → `data/raw/subway/`.
- 같은 역 이름의 여러 호선은 하차를 더한다.
- 역 이름 맞추기: `data/processed/nametags/05_행정동_역_연결표.csv`의 `station`과 맞춘다. 괄호 안 부역명 제거, "역" 접미사 제거 후 비교. 못 맞춘 역은 `reports/gt_midterm/00_unmatched_stations.csv`로.
- **역 → 동 나누기**: 가중치 `w(s, d) = share_1000(d, s) × land_km2(d)` (= 동 d에서 역 s의 1km 원 안 육지 면적), 역마다 합 1로 나눈다. `land_km2`는 `01_행정동_목록.csv`.
- 동 하차 = Σ_s 역 하차 × w(s, d). 연결된 역이 없는 동은 결측 → 이 동은 지하철이 들어간 묶음 평가에서 빠진다 (§6.4 공통 집합).

### 4.2 생활인구

- 출처: 서울시 행정동 단위 생활인구 (OA-14991), 2023-01~2026-07 → `data/raw/living_pop/`.
- 11~21시 평균 → 주 평균. 동 코드는 §3.3과 같은 대응을 쓴다.
- 2026-07 이후는 없다. 이번 예측 시점(마지막 2025-07-27)에는 문제없다.

출력: `data/interim/gt/features_weekly.parquet` — `dong_code8, week_end, <입력들>`

**누수 시험** (`01_features.py` 끝에서 assert): 각 시점에 대해, 예측 13주 각 주의 입력이 참조한 원자료 날짜가 모두 시점 이전인지 확인하고 결과를 로그에 남긴다.

## 5. 모델 (`02_models.py`)

모든 모델은 **`log1p(y)`** 를 적합하고 예측 후 되돌린다. 동마다 따로 적합한다 (국소 모델).

| 모델 | 정의 |
|---|---|
| `naive` | 다음 13주 모두 예측 시점 직전 주 값 |
| `snaive` | 각 주를 52주(364일) 전 값으로 (작년 같은 주) |
| `arima` | `statsmodels` SARIMAX, 계절 없음. (p, d, q) ∈ {0,1,2} × {0,1} × {0,1,2} 중 AIC 최소 |
| `sarima` | `arima`의 차수 + 계절 (P, D, Q, s) = (0, 1, 0, 52) 와 (0, 1, 1, 52) 중 AIC 최소. 계절 차분 = "작년 같은 주 + 보정" |
| `arimax` | `arima` + 외생변수 (입력 묶음별) |
| `sarimax` | `sarima` + 외생변수 (입력 묶음별) |

- 입력 묶음: `none`(= arima/sarima), `search`, `all_noLP`, `all`. M3는 각 묶음에 `y_lag52`를 더한 버전(`+py`)을 따로 돌린다.
- 차수 선택은 **`none` 묶음에서 한 번** 하고, 같은 차수를 외생변수 버전에 쓴다 (비교를 공정하게).
- 적합 실패·수렴 경고는 `results/gt/fit_log.csv`에 남기고, 실패하면 `naive`로 대체하되 `fallback=1`로 표시한다. 대체 비율을 리포트에 적는다.
- 병렬: `joblib`로 동 단위 병렬. 결과는 시점별로 저장해 중간에 끊겨도 이어서 돌릴 수 있게 한다.
- 계산량이 너무 크면 (한 시점 30분 이상 예상) `sarima` 계절 후보를 (0,1,0,52) 하나로 줄이고 리포트에 적는다.

출력: `results/gt/pred_<origin>.parquet` — `origin, dong_code8, week_end, h(1~13), model, xset, y_hat, fallback`

## 6. 평가 (`03_evaluate.py`)

### 6.1 지표

- **WAPE** = Σ|y − ŷ| ÷ Σy × 100. 전체(동 × 13주 합)와 동별 둘 다.
- **MASE** = 동별 MAE ÷ (그 동 학습 구간에서 작년 같은 주 예측의 MAE). 1보다 작으면 작년 같은 주보다 낫다. 동별 값의 중앙값과 평균을 보고.
- **개선 비율** = 기준선보다 동별 WAPE가 낮은 동의 비율.
- **검정**
  - 동별 WAPE 쌍 비교: Wilcoxon 부호순위 검정 (모델 vs `snaive`, 외생변수 있음 vs 없음).
  - DM 검정(HLN 보정): 서울 전체 주별 절대오차 합을 4개 시점 × 13주로 이어 붙여 비교. 시점이 4개뿐이라 참고용이라고 적는다.

### 6.2 표 (리포트에 넣는 것)

1. **주 결과표**: 행 = 모델(naive, snaive, arima, sarima, arimax, sarimax), 열 = 입력 묶음(none, search, all_noLP, all), 값 = 4개 시점 평균 WAPE. 가장 좋은 칸 굵게.
2. **시점별 표**: 행 = 시점, 열 = 주요 모델·묶음, 값 = WAPE. 2025-04-27 행은 중간발표 초안 숫자(작년 같은 주 8.52%, SARIMAX + 과거 이동 18.93%, + 검색 16.28%)와 나란히 적어 재현 여부를 보인다.
3. **M3 표**: 각 모델·묶음에서 `y_lag52`를 넣기 전/후 WAPE와 차이, Wilcoxon p값.
4. **M4 표**: 검색 원지수 vs 서울 대비 비중 (검색 묶음, ARIMAX·SARIMAX).
5. **동별 분포 표**: 모델별 동 WAPE의 10·25·50·75·90 백분위, 개선 비율.

### 6.3 419동 비교

## 7. 핫스팟 (`04_hotspots.py`)

### 7.1 정의 (README §2.2)

시점 o마다 세 가지 목록을 만든다.

| 목록 | 계산 |
|---|---|
| **현재 (실제)** | o 직전 13주 실제 `y` 평균 상위 10% = 현재 핫스팟. 같은 13주 평균 `share`의 1년 전 같은 13주 대비 증가율 상위 10% (현재 규모 하위 25% 제외) = 떠오르는 곳 |
| **예측** | o 다음 13주 **예측** 평균으로 같은 계산. 증가율의 분모는 1년 전 같은 13주 **실제** `share` (이미 관측). 예측 share = 예측 y ÷ 예측 서울 합계 (서울 합계는 427동 예측 합) |
| **실제 (정답)** | o 다음 13주 **실제** 평균으로 같은 계산 |

- 규모 하위 25%는 시점 o 직전 13주 실제 평균 기준으로 정한다 (예측과 실제 모두 같은 제외 집합).

### 7.2 상위 K개 적중률 (M6)

- 적중률@K = |예측 상위 K ∩ 실제 상위 K| ÷ K. K = 10, 20, 30, 그리고 상위 10%(약 42개).
- 대상: 떠오르는 곳(증가율 순위), 현재 핫스팟(수준 순위) 둘 다.
- 비교 기준
  - **무작위**: 기대값 K ÷ 대상 동 수
  - **지속**: o 직전 13주의 1년 전 대비 증가율 순위를 그대로 다음 13주 예측으로
  - **작년 같은 주(`snaive`)**: 모든 동의 예측 증가율이 0이라 **순위를 매길 수 없다**. 표에 "해당 없음"으로 적고 이유를 한 줄 쓴다
- 모델: 주 결과표에서 WAPE가 가장 좋은 모델 2~3개.

### 7.3 민감도 (간단히)

- 상위 5·10·20%, 규모 제외 0·25%, 목적 4+5 vs 4+5+7, 20~39세 vs 전 연령으로 **실제** 떠오르는 곳 목록을 다시 만들고, 기본 목록과 겹치는 비율(Jaccard)을 표로 낸다.

출력: `reports/gt_midterm/tables/hotspots_<origin>.csv` (동, 구, 값, 순위, 목록 종류), `topk.csv`, `sensitivity.csv`

## 8. 그림 (`05_figures.py`)

**공통 원칙**
- 예측은 주 단위, 그림은 **13주 예측 구간을 중심으로** 보여 준다. 예측 구간은 옅은 음영으로 표시하고, 예측 시점에 점선 세로선을 긋는다.
- 선 스타일 (중간발표 두 번째 초안과 같게)
  - 예측 시점까지 실제: 진한 파랑 실선 `Observed by cutoff`
  - 예측 시점 이후 실제: 파랑 점선 `Later observed`
  - 외생변수 없는 예측: 회색 실선 `No X: <WAPE>%`
  - 외생변수 있는 예측: 빨강 실선 `With X: <WAPE>%`
  - **작년 같은 주**: 초록 가는 점선 `Prior-year same week: <WAPE>%` (두 번째 초안에 없던 선. 꼭 추가)
- 범례 안에 각 선의 13주 WAPE를 적는다.
- 축 제목·단위 표시. 그림 제목에 결론을 한 문장으로 (예: "화곡1동: 검색을 넣으면 13주 오차가 5.9% → 2.5%").
- png, 150dpi 이상. `reports/gt_midterm/fig/`.
