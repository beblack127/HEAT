## 1. 한 행과 목표값

**한 행 = 행정동 코드 `d` × 예측 대상 월 `m`.** 매월 1일에 그 달의 이동량을 예측한다고 가정한다. 표적은 서울시 수도권 생활이동의 **내국인 도착 행정동 기준 목적 4(쇼핑)+5(관광)+7(기타)** 월별 일평균이다.

`y[d,m] = 해당 월 도착 이동 추정량(목적 4+5+7)의 일별 합 / 유효 관측 일수`

이 값은 관광객 수나 실제 상권 방문자 수가 아니라 **비정기 목적 이동의 대리 지표**다. 목적 7의 범위가 넓으므로 `4+5`만의 규모와 주 결과 민감도를 별도 제시한다.

**목표값을 두 가지로 나눠 평가한다.**

| 목표 | 정의 | 답하는 질문 |
|---|---|---|
| 수준 `y[d,m]` | 위 정의 그대로 (모델 안에서는 `log y`) | 지금 사람이 많이 오는 동은 어디인가 (현재 핫스팟) |
| 변화 `g[d,m]` | `log(y[d,m] / y[d,m−12])` | 1년 전보다 얼마나 늘었나 (떠오르는 동) |

- 수준만 평가하면 큰 동이 계속 크기 때문에 어떤 모델이든 좋아 보인다. 검색 비중·개업 수의 동 순위는 해마다 순위상관 0.91~0.998로 거의 그대로였다.
- **'뜨는 동'은 `g`의 예측값 상위 K개 동**으로 정한다. 최소 이동량 조건은 사전에 고정한다. 기본값으로는 학습 구간 수준이 하위 25%인 동을 뺀다. 작은 동은 증가율이 쉽게 튀기 때문이다.
- 계절 기준선 대비 초과분을 쓰려면, 그 기준선은 fold 학습 구간 자료로만 만든다.

## 2. 실제 학습 표의 열

아래 `lag2`는 대상 월 `m`의 두 달 전 관측값을 뜻한다. **실제 첫 공개 날짜가 더 늦으면 시차를 늘려야 한다.** 모든 원자료에는 관측 월, 첫 공개/수정 날짜, 다운로드 버전을 기록한다.

| 원자료 | 만드는 열 예시 | 모델에서의 역할 | 결합·주의 |
|---|---|---|---|
| 수도권 생활이동 목적별 내국인 | `y`, `y_lag2`, `y_lag3`, `y_lag12`, 최근 3개월 평균, 전년 동월비 | `y`가 유일한 주 GT. 과거 `y`가 핵심 학습 정보 | 도착 행정동 8자리 코드로 일·목적을 월 단위 집계. ARIMA 계열에는 `log y` 시계열 자체를 넣고, 시차표는 기준선·EDA·전역 모델에 쓴다. 예측 월의 `y`는 입력 금지. |
| 재현의 이름표 `01`·`02`·`04` | 코드, 동명, 검색어 묶음, 연결 가중치 | 공간 결합표. 검색할 장소명 정의 | 427개 동은 **2025-12-31 행정동 경계** 기준이다. 시간별 공식 코드와 대조하는 대응표를 만든다. 2025년 이후 생긴 동의 과거 `y`를 임의로 나누지 않는다. 여러 동에 걸친 검색어는 실제 방문을 배분한 수치로 해석하지 않는다. |
| 재현의 네이버 검색 시계열 | 우선 하나: `search_share_lag2` (서울 대비 비중, log) 또는 `search_chg3sa_lag2` (계절 보정 3개월 변화) | 핵심 후보 외생변수 X: 사전 관심 | GitHub `data/processed/search/행정동_검색지수_월별.csv`, 칸 `전체`. **절대 지수(`index`)가 아니라 `seoul_share`를 쓴다.** `chg_3m_sa`와 `seasonal_factor`는 CSV에 2022~2024 기준으로 들어 있으므로 fold마다 **2023-01부터 그 fold 학습 끝까지**의 자료로 다시 계산한다. `chg_12m`처럼 1년 전 값이 필요한 열도 2023-01 이후 값으로 다시 만든다(2024-01부터 값이 생김). 지수가 없는 5개 동은 결측으로 표시한다. |
| 음식점 인허가 원자료 (재현) | 우선 하나: `food_stock_chg12_lag2` (영업 점포 12개월 변화율) 또는 `food_open_12m_lag2` (12개월 개업 수). 민감도: `food_net_rate_3m_lag2` | 후보 X: 상권 공급·변화 | 일반·휴게음식점 합침, 편의점·구내매장 등 제외. 점포 좌표를 2025-12-31 경계 행정동에 붙였다. 일괄 폐업은 뺀 버전(`v_drop`)이 기본이다. 같은 날 대량 개업 + 일괄 폐업인 동(장충·묵2·공릉2·가락1)은 재등록 플래그를 붙인다. |

| 달력 | 대상 월의 주말·공휴일 수, 월 | 사전에 확정 가능한 X | 목표 월의 달력은 미래 정보 누출이 아니다. 일평균 목표값이어도 요일 구성 차이가 남는다. |
| 상권분석서비스 길단위인구·점포·매출 | 우선 학습 열 없음 | 보조 설명·외부 타당성 확인 | 분기 단위, 공간 단위·배포 변경, 발표 지연을 먼저 점검. 음식점 **인허가 원자료**와 상권분석서비스 점포 수를 같은 자료로 혼동하지 않는다. |
| S-DoT 등 장소 센서 | 학습 열 없음 | 제한적 외부 확인 | 센서 장소·기간이 맞을 때만 실제 활동 변화 방향을 비교한다. |

- 검색은 2022-01~2026-10(422동), 인허가는 2015-01~2026-10(427동)까지 있지만, **모든 자료를 2023-01 이후 값만 학습에 쓴다.**
  - 그래서 12개월 시차가 필요한 열(`y_lag12`, `search_chg12`, `food_stock_chg12`, `food_open_12m`)은 2024-01부터 값이 생긴다. 2023년 행에서는 결측으로 둔다.
  - 영업 점포 수는 그 달에 영업 중인 점포를 센 값이다. 2023년 이전에 문을 연 점포도 포함되지만, 2023-01 시점의 상태라서 이 규칙에 어긋나지 않는다.
  - 검색어 제외 목록(2022년 검색량이 너무 적은 묶음 등)은 검색어를 고르는 사전 규칙으로 이미 고정돼 있어 그대로 쓴다. 학습 자료가 아니고, 모든 시험 구간보다 앞선 자료로 정했다.
- 동×월 검색 지수는 이미 GitHub에 있다. 동×월 개업·폐업·영업 점포 표와 산출 코드(`src/forecast/`)는 재현이 GitHub에 올린 뒤 받는다.
- 재현의 리포트에 있는 검색·개폐업 자체의 예측 성능은 생활이동 예측 성능이 아니다. 다만 같은 동·같은 기간의 시계열이라 어떤 일이 생길지 미리 알려 준다(§8).

## 3. 예측 시점 예시와 누출 방지

**2026년 6월 1일에 6월을 예측**한다면, 주 실험에서는 생활이동과 모든 동적 보조 지표를 **2026년 4월분까지** 쓴다. 목표 열은 2026년 6월 `y`이고 학습 입력에는 나타나지 않는다.

**자료별로 실제 쓸 수 있는 시점이 다르다.** 그래서 '빠른 정보' 실험을 따로 둔다.

| 자료 | 주 실험 | 빠른 정보 실험 | 근거 |
|---|---|---|---|
| 생활이동 | `lag2` | `lag2` | 공개 시점 확인 전까지 보수적으로 |
| 검색 | `lag2` | `lag1` | 월 값은 다음 달 초에 API로 받을 수 있다 |
| 음식점 인허가 | `lag2` | `lag1` | 폐업 기록의 99%가 폐업일 30일 안에 반영된다 |
| 지하철 | `lag2` | 공개일 확인 후 결정 | |

ARIMAX/SARIMAX에서는 모형이 목표 월 `m`에 요구하는 외생변수 열을 `X_m := 원자료 X_(m-2)`로 미리 이동시킨다. 그러면 `m-2`까지 관측한 상태에서 2개월 앞 예측에 필요한 `X_(m-1)`, `X_m`은 각각 원자료 `m-3`, `m-2`여서 미래 X를 따로 예측할 필요가 없다. 이 정렬을 코드에서 검증한다.

**fold 학습 구간에서만 정하는 것**
- 표준화, 계절 계수(검색 `seasonal_factor` 포함), 하이퍼파라미터, 최소 이동량 조건의 경계값.
- 이 값들은 모두 2023-01부터 그 fold 학습 끝까지의 자료로 계산한다.
- 검색어 제외 목록은 이미 고정돼 있다(§2). 모델 결과를 본 뒤 바꾸지 않는다.

**네이버 척도는 다시 조회하지 않아도 된다.** API의 `ratio`는 요청 구간 안 최댓값 100으로 표준화되지만, 재현의 수집은 모든 요청에 같은 기준 묶음('문래 맛집·카페·술집·데이트·가볼만한곳')을 넣고 그 값으로 척도를 맞췄다. 결과 척도는 '기준 묶음의 2022년 월평균 = 100'으로 고정되어, 조회 기간을 늘려도 과거 값이 바뀌지 않는다. 이 '2022년 = 100'은 단위를 정한 것일 뿐이라, 2023년부터 학습하는 규칙과 부딪히지 않는다. 게다가 `seoul_share`로 바꾸면 단위가 사라진다. 431개 요청에서 기준 묶음 모양의 상관은 1.0000이었다. 원본 요청·응답은 `data/raw/search_api/`에 있다. 동별 비중(`seoul_share`)은 그 달 안에서만 나누므로 미래 정보가 들어가지 않는다.

## 4. 모델 실험 순서

| 단계 | 모형 | 입력 | 답할 질문 |
|---|---|---|---|
| B0 | Naive: `y_(m-2)` 그대로 | 과거 생활이동 | 가장 단순한 예측보다 나은가? |
| B1 | 계절 naive: `y_(m-12)` | 과거 생활이동 | 계절 반복보다 나은가? |
| M1 | ARIMA | 동별 과거 생활이동 | 추세가 도움이 되는가? |
| M2 | SARIMA | 동별 과거 생활이동 + 계절항 | 월별 계절성이 도움이 되는가? |
| E | ETS (계절 12) | 동별 과거 생활이동 | 단순 평활이 ARIMA 계열과 비슷한가? |
| M3a | ARIMAX | 생활이동 + **검색 요약 1개** | 사전 관심이 예측력을 더하는가? |
| M4a | SARIMAX | 생활이동 + **같은 검색 요약 1개** | 계절성을 고려해도 효과가 남는가? |
| M3b/M4b | ARIMAX/SARIMAX | 검색 대신 음식점 변화 1개, 역 하차 1개, 생활인구 1개를 **각각** | 어떤 보조 자료가 도움이 되는가? |
| M3c/M4c | ARIMAX/SARIMAX | 검증에서 효과가 확인된 변수 1~2개 | 함께 쓸 때도 좋아지는가? |
| G0 / G1 | 전역 Ridge (모든 동을 한 모델로) | G0: 생활이동 시차 + 달력. G1: G0 + M3에서 쓴 변수 1개씩 | 동별 계수로 안 보이는 작은 효과가 모아서 보이는가? |

- 모든 단계를 **같은 동·월·예측 거리**로 비교한다. 검색 결측 5동 때문에 표본이 줄면, 검색을 넣지 않은 모델도 같은 422동·월로 다시 평가한다.
- 동별 월 이력이 약 24~46개다. 그래서 계절 SARIMA와 SARIMAX의 차수는 단순하게 고정하고, 실패·수렴 여부를 함께 보고한다. 재현의 개폐업·검색 예측에서는 학습 24개월일 때 AutoARIMA가 대부분 계절 항 없는 차수를 골랐다.
- **외생변수 효과는 작다고 보고 설계한다.** 같은 변수를 동별 ARIMAX와 전역 G1 두 곳에서 넣고 빼서 비교한다. 두 곳에서 같은 방향일 때만 "도움이 된다"고 쓴다.
- 최종 발표에 4개 모형만 요구되면 M1·M2·M3a·M4a를 주 표로 둔다. B0·B1은 필수 기준선이고, E·G0는 부록 비교로 둔다.

## 5. 학습·검증·최종 시험

현재 공개 페이지에는 생활이동 목적별 내국인 파일이 **2023-01~2026-10** 있다. 아래는 **품질 점검을 통과한다는 조건의** 시간순 설계다.

| 구간 | 제안 | 용도 |
|---|---|---|
| 첫 학습 | 2023-01~2024-05 (모든 자료 공통) | 첫 대상 월 2024-07을 `lag2`로 예측할 때의 적합 구간. 계절 모형에 17개월은 짧으므로 차수를 고정하고 결과는 보수적으로 해석한다. 12개월 시차 열은 2024-01부터라 전역 모델(G0·G1)의 첫 학습 행은 5개월뿐이다. 전역 모델은 학습 행이 12개월 이상 쌓인 origin(대상 월 2025-02~)부터 평가하거나, 12개월 시차 열을 뺀 버전으로 2024-07부터 평가한다. |
| 개발 검증 | 대상 월 **2024-07 ~ 2025-08**, 매달 origin을 한 달씩 옮김 (확장 창) | 외생변수 선택, 차수·변환 선택. **2024-07~12와 2025-01~08을 나눠 보고한다.** 한 구간에서만 이기는 결과는 채택하지 않는다. |
| 품질 점검 | 2024-08~10 급증, 2025-09 이후 원천 차이 | 해당 월에 플래그를 붙이고, 넣은 결과와 뺀 결과를 모두 적는다. 원인을 모르면 구간별 성능을 분리하고 최종 확정 주장을 보류한다. 2025-09~12는 점검을 통과하면 개발 검증에 더한다. |
| 최종 시험 | 2026-01~10 | 검증에서 고른 규칙을 고정하고 커밋한 뒤 **한 번만** 평가한다. 외생변수는 `lag2` 기준 2026-08까지만 필요해 검색·음식점 자료로 모두 채울 수 있다. 생활인구는 2026-07까지라 2026-09·10에는 쓸 수 없다. |

- 개발 검증을 한 해로만 두지 않는 이유: 재현의 검색 비중 예측은 2024년에는 계절 naive보다 오차가 약 25% 작았지만, 2025년에는 차이가 없었다(p = 0.86). 2025년에 동별 월 변동이 두 배가 됐기 때문이다. 한 해만 보면 반대 결론을 낼 수 있다.
- 실제 운영 모의에서는 월 `m`의 1일을 origin으로 하고 자료 공개일을 재현한다. 다만 지금 내려받는 2023~2025 파일 중 일부는 나중에 다시 배포된 것이다. 과거에 그 값이 *실제로 공개돼 있었는지* 확인하지 못하면 '현재 배포본을 사용한 회고적 백테스트'라고 명시한다.
- 2025년 용신동 분리 등 과거 개별 시계열이 없는 동은 `not_estimable`로 표시한다.

## 6. 평가 지표

| 지표 | 대상 | 정의·이유 |
|---|---|---|
| MASE | 수준 `y`, 변화 `g` | 모델 오차 ÷ 학습 구간 계절 naive 오차. 1보다 작으면 계절 naive보다 낫다. 동마다 규모가 달라도 비교할 수 있다. |
| WAPE, MAE | 수준 `y` | 전체 규모 오차. 큰 동에 치우치므로 동별 오차 분포와 함께 보고한다. |
| 상승 상위 K개 적중률 | 변화 `g` | 예측 상위 K개 동 중 실제 상위 K개에 든 비율, K = 10, 20, 30. **Naive와 무작위(K / 동 수) 값을 같은 표에 둔다.** 큰 동이 계속 크기 때문에 Naive도 높게 나올 수 있다. |
| DM 검정 | 모델 비교 | Diebold-Mariano, HAC 시차 h − 1, HLN 소표본 보정. 오차 차이만으로 "개선"이라고 쓰지 않는다. origin이 적고 예측 구간이 겹치므로 p값은 참고로 본다. |

- 결과는 개발 구간별(2024 하반기, 2025 1~8월)로 따로 적고, 평균 하나로 결론 내리지 않는다.
- 서울 전체·구·동 수준별 성능을 함께 보고한다. 개폐업에서는 서울 전체에서는 계절 naive가 가장 좋았고, 동에서는 평활 모델이 이겼다.

## 7. 자료별 준비 우선순위

1. **P0:** 2023~2026 생활이동 목적별 월 집계와 월별 공식 동 코드, 품질·배포 이력. 2025-12-31 경계 427동과의 대응표. 이것만으로 B0·B1·M1·M2·E·G0 가능.
2. **P1:** 재현의 동×월 검색 비중 표(GitHub에 있음)와 음식점 개업·폐업·영업 점포 표(재현이 GitHub에 올릴 예정), 산출 코드와 조회 기준. 이를 받아 ARIMAX·SARIMAX·G1 증분 실험.
3. **P2:** 2026 역 하차량과 역사 변경 이력. 접근 신호 실험.
4. **보조 실험:** 2026-07까지의 행정동 생활인구. 같은 기간으로만 모델을 비교한다. 분기 상권 자료와 현장 센서는 설명·외부 확인을 우선한다.

## 8. 근거: 검색량·개폐업 예측에서 확인된 것

재현의 리포트(2026-11-12)에서 이 설계와 관련된 결과만 모았다. 학습 2022~2023 → 시험 2024, 학습 2022~2024 → 시험 2025, 3개월 앞 예측이다. **이 결과는 2022년부터 학습한 것이다.** 이 설계는 2023년부터 학습하므로 학습 기간이 1년 더 짧다. 그래서 아래 "짧은 학습에서 SARIMA 약함"은 더 강하게 나타날 수 있다.

| 확인된 것 | 수치 | 이 설계에 주는 뜻 |
|---|---|---|
| 해에 따라 결론이 뒤집힘 | 검색 비중: 2024년 MASE 0.97(유의), 2025년 2.25(계절 naive 2.20, p = 0.86) | 검증 구간을 연도별로 나눠 본다 (§5) |
| 2025년 변동 급증 | 동별 검색 비중 월 변동폭 중앙값 2023년 3.2% → 2025년 6.5% | 2025년 이후 구간은 따로 해석 |
| 규모는 지속, 변화는 비지속 | 동 순위상관: 검색 비중 0.99, 개업 수 0.91~0.93, 순증률 0.11~0.19 | 수준과 변화를 따로 평가 (§1) |
| 변화는 되돌아감 | 검색 비중 3개월 변화와 다음 3개월 변화의 순위상관 −0.26 ~ −0.36 | 변화 변수의 계수가 음수일 수 있음 |
| 교차 효과가 작음 | 검색↔개폐업을 서로 넣어도 대부분 같거나 조금 나빠짐, LightGBM 중요도 0.4~5% | 동별 계수와 전역 넣기/빼기를 함께 본다 (§4) |
| 짧은 학습에서 SARIMA 약함 | 학습 24개월에서 AutoARIMA가 대부분 계절 항 없는 차수 선택 | 차수 고정, ETS·전역 모델 비교 (§4) |
| 집계 수준마다 1등이 다름 | 개업 수: 서울은 계절 naive(0.13 / 0.89), 동은 Ridge·ETS(0.95 / 0.99) | 계절 naive 필수, 수준별 보고 (§6) |
| 서울 전체 검색 감소 | 서울 검색 지수 연평균 2022년 27,151 → 2025년 23,457 (−14%) | 검색은 서울 대비 비중으로 (§2) |
| 동 개폐업은 잡음이 큼 | 동별 월 개업 중앙값 2건, 3개월 개업 합 평균 오차 3.5~3.8건 | 음식점 변수는 12개월·점포 기반 (§2) |
| 일괄 폐업 증가 | 전체 폐업 중 비중 4% → 2024년부터 9~10%. 넣으면 폐업 예측 오차 15~20% 증가 | `v_drop` 기본, 재등록 플래그 (§2) |
| 폐업 신고 지연 작음 | 폐업 기록 99%가 30일 안에 반영 | 음식점 `lag1` 실험 가능 (§3) |
