# HEAT

시계열적 요소를 종합하여 서울 시내의 핫플레이스를 정의하고 떠오르는 지역을 예측하는 시스템

한양대학교 시계열데이터분석및실습 Team #14. 서울 427개 행정동을 단위로 **지금의 핫스팟**과 **떠오르는 곳**을 찾는다.

```
            입력 (2022-01 ~)                       정답 (2023-01 ~)
  ┌──────────────────────────────┐        ┌──────────────────────────────┐
  │ 네이버 검색량 (관심)          │        │ 생활이동 도착량               │
  │ 음식점 개폐업 (공급)          │ ─────▶ │ 20~39세, 목적 4+5+7           │
  │ 과거 생활이동, 지하철, 달력   │  예측   │  · 수준 y  → 현재 핫스팟     │
  └──────────────────────────────┘        │  · 1년 변화 g → 떠오르는 곳   │
                                          └──────────────────────────────┘
                     결과는 행정동 지도(maps/)로 본다
```

## 1. 지금까지 한 것

### 1.1 행정동 이름표

사람들이 어떤 이름으로 그 동을 검색하는지 정했다. 동마다 세 종류의 이름을 붙이고 가중치를 줬다.

| 칸 | 기준 | 예 |
|---|---|---|
| 동네 | 법정동 면적이 행정동 육지 면적의 10% 이상 | 성수동, 연남동 |
| 역 | 같은 강변 1,000m 원 안 육지 면적이 5% 이상 | 성수역, 뚝섬역 |
| 상권 | 상권 영역 면적의 10% 이상이 동 안 | 서울숲 카페거리 |

- 결과: 427동, 이름 묶음 566개. `data/processed/nametags/01~07`
- 자세한 규칙: `reports/nametags/00_결과_요약.md`

### 1.2 네이버 검색량

- **수집**: NAVER API HUB 검색어 트렌드로 566묶음 × 방문 의도어 6개(맛집, 카페, 술집, 데이트, 가볼만한곳, 핫플)를 모았다. 기간은 2022-01~2026-10, 월 단위다.
- **척도**: 모든 요청에 같은 기준 묶음(문래)을 넣어 척도를 맞췄다. 조회 기간을 늘려도 과거 값이 바뀌지 않는다.
- **동별 지수**: 서울 전체 검색량이 2022→2025년 14% 줄어서, 동 비교는 **서울 대비 비중**으로 한다.
  - 변화는 네 가지로 본다: 지난달, 3개월, 3개월 계절 보정, 1년.
  - 검색량이 너무 적거나 다른 뜻과 겹치는 묶음 160개를 뺐다(예: 방학, 양평).
- **결과**: 지수가 있는 동 422개. `data/processed/search/행정동_검색지수_월별.csv`
- 자세한 내용: `reports/search/00_검색량_요약.md`

### 1.3 음식점 개폐업

- **자료**: 서울시 인허가 일반·휴게음식점에서 편의점·구내매장 등을 뺐다. 점포 좌표로 2025-12-31 경계 행정동에 붙였다(93.7%).
- **동×월 표**: `data/processed/fnb/행정동_개폐업_월별.csv` (2022-01~2026-09, 서울·구·동)

  | 열 | 뜻 |
  |---|---|
  | `개업` | 그 달 개업 수 |
  | `폐업_일괄제외` | 그 달 폐업 수. 같은 날 한꺼번에 처리된 행정 정리(일괄 폐업)는 뺌. **기본값** |
  | `폐업_일괄포함` | 일괄 폐업을 포함한 폐업 수 |
  | `영업점포` | 그 달 말 영업 중인 점포 수 |
  | `영업점포_<업종>` | 업종 12개별 영업 점포 |

- **점검 결과**:
  - 일괄 폐업이 2024년부터 두 배가 됐다(전체 폐업의 4% → 9~10%).
  - 폐업 기록의 99%가 폐업일 30일 안에 반영된다.
  - 장충동·묵2동·공릉2동·가락1동은 행정 재등록으로 보여 순위에서 뺀다.
  - 2026-10은 일부만 집계돼 쓰지 않는다.

### 1.4 지도 시스템

`maps/행정동_검색량_개폐업_지도.html`을 브라우저로 연다. 파일 하나로 열리고, 인터넷이나 키가 필요 없다.

| 탭 | 지도 색 | 동을 누르면 |
|---|---|---|
| 검색량 | 검색 지수, 또는 서울 대비 변화(지난달·3개월·3개월 보정·1년) | 월별 추이, 칸별·이름별 추이 |
| 개폐업 | 개업·폐업 수, 순증률, 점포 증감 (1·3·12개월) | 월별 개업·폐업, 영업 점포, 업종 구성 |
| 이름표 | 붙은 이름 종류 수 | 동네·역·상권 이름과 가중치, 근거 |

- 표시 기간: 2022-01부터 (검색량 ~2026-10, 개폐업 ~2026-09)
- 지하철역, 랜드마크, 상권 경계 표시
- 개폐업 탭: 일괄 폐업을 넣고 빼서 볼 수 있다. 점포 30개 미만 동은 비율을 칠하지 않는다.

### 1.5 검색량·개폐업 예측 실험

검색량과 개폐업 자체를 2022~2025년으로 학습해 3개월 앞을 예측해 봤다. 정답 모델에 넣기 전에 두 자료의 성질을 알기 위한 실험이다.

- 계획: `docs/forecast_plan.md` · 코드: `src/forecast/` · 리포트: `reports/forecast/00_결과_리포트.md`
- 검증: 학습 2022~2023 → 시험 2024, 학습 2022~2024 → 시험 2025
- 모델: Naive, 계절 Naive, ETS, Theta, SARIMA, Croston/TSB, SARIMAX, LightGBM, Ridge

| 확인한 것 | 수치 | 뜻 |
|---|---|---|
| 개폐업은 기준선을 넘는다 | 동별 개업·폐업·순증률 MASE 0.92~0.99 (계절 naive 1.12~1.26), 두 해 모두 유의 | 단순한 ETS·Ridge로 충분 |
| 검색은 2024년만 맞혔다 | 2024 MASE 0.97(유의), 2025 2.25(계절 naive 2.20과 차이 없음) | 해마다 결론이 달라질 수 있다 |
| 3개월을 넘으면 예측력이 사라진다 | 12개월 앞 개업 수는 Naive와 같다 | 예측 거리는 짧게 |
| 검색과 개폐업은 서로 돕지 않는다 | 서로 넣어도 같거나 조금 나빠짐 | 3개월 안에서는 별개 신호 |
| 큰 곳은 계속 크고, 크는 곳은 바뀐다 | 동 순위상관: 검색 비중 0.99, 개업 수 0.91~0.93, 순증률 0.11~0.19 | "떠오르는 곳"은 따로 평가해야 한다 |
| 서울 음식점은 2024년부터 줄고 있다 | 영업 점포 2023년 말 최고 → 2년간 −3.9% | 2025년이 더 어렵다 |

**현재 핫스팟과 떠오르는 곳** (기술 통계, 2026년 가을 기준)

| | 현재 핫스팟 | 떠오르는 곳 |
|---|---|---|
| 검색 | 성수, 용산(한강로·용산2가·이촌2), 잠실 | 광진구 군자역~아차산 일대(군자·능동·중곡1·2) |
| 개폐업 | 삼성1동(코엑스), 여의동, 영등포동, 한강로동 | 을지로동(2년 연속 점포 증가) |

## 2. 정답(G.T)을 무엇으로 할까

### 추천: 생활이동 비정기 목적 도착량

**주 정의**: 20~39세, 목적 4(쇼핑)+5(관광)+7(기타), 도착 행정동 기준 월 일평균

| 후보 | 장점 | 정답으로 쓰기 어려운 점 | 역할 |
|---|---|---|---|
| **생활이동 4+5+7** | 실제로 "놀러 온" 양에 가장 가까움. 동·월 단위 | 통계적 추정치. 품질 이슈(2024-08~10 급증, 2025-09~ 원천 변경, 이촌2동 급락). "기타"가 넓음. 2023-01부터 | **정답** |
| 네이버 검색량 | 관심이 먼저 보임. 2022년부터 | 방문이 아닌 관심, 전국 검색, 상대 지수. 우리가 만든 지표라 정답으로 두면 자기 입력을 맞히는 셈 | 입력, 선행 신호 |
| 음식점 개폐업 | 공급 변화. 2015년부터 | 수요를 늦게 따라옴. 동 단위 잡음 큼(월 개업 중앙값 2건). 재등록·일괄 폐업 | 입력, 정착 확인 |
| 지하철 하차 | 실측 | 역 단위, 출퇴근 섞임 | 외부 검증 |
| 생활인구 | 실측에 가까움 | 2026-07 생산 종료, 거주·직장 섞임 | 보조 실험 |
| 상권 매출 | 돈의 흐름 | 분기 단위, 공개 늦음, 방문과 어긋남(명품거리) | 설명용 |

민감도: 목적 4+5만, 전 연령.

### 정답 타당성 점검 (모델링 전에)

정답은 **예측이 잘 되는 쪽으로 고르지 않는다.** 맞히기 쉬운 것을 정답으로 고르는 셈이 되기 때문이다. 대신 "이 정답이 핫플레이스를 제대로 가리키는가"를 아래 네 가지로 확인한다. 후보 정의와 통과 기준은 결과를 보기 전에 고정한다.

1. **알려진 핫플**: 미리 정한 목록(성수·연남·용산·을지로·한남 등)이 정답 순위 상위 몇 %에 드는가
2. **외부 신호와의 방향**: 동×월 단위로 지하철 하차, 검색 비중, 영업 점포 증감과 같은 방향으로 움직이는가 (수준, 1년 변화)
3. **품질**: 갑자기 튀거나 꺼지는 동·월이 얼마나 많고, 문제 구간에 몰려 있는가
4. **정의 민감도**: 4+5+7과 4+5, 20~39세와 전 연령으로 만든 동 순위의 순위상관

## 3. 무엇으로 무엇을 예측하고 무엇을 검증하나

### 예측 대상

| 대상 | 정의 | 뜻 |
|---|---|---|
| 수준 y | 동별 월 생활이동 일평균 | **현재 핫스팟** |
| 변화 g | log(y ÷ 1년 전 같은 달 y) | **떠오르는 곳** |

- m월을 m−2월까지의 자료로 예측한다 (생활이동 공개 시차).
- 지도와 입력 자료는 2022-01부터 보여 준다. 정답이 2023-01부터라 **정답 모델의 학습·평가는 2023년부터**다. 변화 g는 2024-01부터 계산된다.

### 입력

| 묶음 | 열 (모두 2개월 전 값) |
|---|---|
| 과거 정답 | 2·3·12개월 전 y, 최근 3개월 평균 |
| 검색량 | 서울 대비 비중, 계절 보정 3개월 변화 (계절 계수는 fold마다 다시 계산) |
| 개폐업 | 영업 점포 12개월 변화율, 12개월 개업 수 (일괄 폐업 제외) |
| 기타 | 지하철 하차, 달력(주말·공휴일 수). 생활인구는 보조 실험 |

### 모델

| 단계 | 모델 |
|---|---|
| 기준선 (필수) | 지난 값 그대로, 1년 전 같은 달 |
| 국소 | ARIMA, SARIMA, ETS |
| 외생변수 | ARIMAX, SARIMAX (변수 하나씩) |
| 전역 | 모든 동을 묶은 Ridge (같은 변수 넣기/빼기) |

### 검증: 세 가지 질문

| 질문 | 방법 | 판단 기준 |
|---|---|---|
| ① 정답을 잘 맞히나 | 대상 월 2024-07~2025-08을 한 달씩 옮기며 예측, **2024 하반기와 2025를 나눠 보고**. 최종 2026-01~10은 모든 선택을 고정한 뒤 한 번만 | 1년 전 같은 달 대비 MASE, WAPE, DM 검정(HAC, HLN 보정) |
| ② 검색·개폐업이 도움이 되나 | 같은 모델에서 그 변수만 넣고 뺌 (동별 ARIMAX와 전역 Ridge 둘 다) | 두 구간·두 방식 모두 같은 방향일 때만 "도움 된다" |
| ③ 핫스팟을 제대로 집어내나 | 예측 g 상위 K개(10·20·30) 중 실제 상위 K개 비율. 뽑힌 동에서 이후 개업·검색·하차가 따라오는지 | Naive·무작위 대비 적중률, 성수·용산·군자 사례 |

## 4. 앞으로 할 실험

- [ ] **정답 자료 준비**: 생활이동 2023-01~2026-10 동×월 집계, 공식 동 코드와 2025-12-31 경계 427동 대응표
- [ ] **정답 타당성 점검** (§2): 후보 정의·핫플 목록·통과 기준을 먼저 고정하고 실행
- [ ] **기준선과 국소 모델**: 지난 값, 1년 전 같은 달, ARIMA, SARIMA, ETS
- [ ] **외생변수 실험**: 검색 → 개폐업 → 지하철 → 생활인구 순서로 하나씩 넣고 빼기
- [ ] **핫스팟 판정 평가**: 변화 g의 top-K 적중률, 이후 신호 확인, 사례 분석
- [ ] **품질 구간 민감도**: 2024-08~10, 2025-09~ 를 넣은 결과와 뺀 결과
- [ ] **최종 시험**: 커밋 해시를 기록하고 2026-01~10을 한 번 실행
- [ ] **지도 연결**: 예측 y·g와 핫스팟 판정을 지도에 탭으로 추가

예측 결과 표는 이 형식으로 맞춘다. 평가와 지도가 같은 표를 읽는다.

```
dong_code8, month, model, y_hat, g_hat, rank_g
```
