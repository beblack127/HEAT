# 생활이동 GT 기반 모델 학습용 데이터 설계

작성일: 2026-11-12. 이전 `FULL_PIPELINE_427.md`보다 최신 공개 범위(생활이동 2026-10)와 행정동 생활인구 생산 종료(2026-07)를 반영한 제안이다. **아래 변수의 효과는 아직 실험 결과가 아니다.**

> 2026-11-14 팀 수정본과 중간발표 공지를 검토한 선택 사항은 [FEEDBACK_DECISIONS_2026-11-14.md](FEEDBACK_DECISIONS_2026-11-14.md)에 정리했다. 특히 두 기준선, 성장 순위 보조 평가, 검색 척도 감사, 40동 파일럿의 부정적 결과를 발표에 반영한다.

## 1. 한 행과 목표값

**한 행 = 행정동 코드 `d` × 예측 대상 월 `m`.** 매월 1일에 그 달의 이동량을 예측한다고 가정한다. 표적은 서울시 수도권 생활이동의 **내국인 도착 행정동 기준 목적 4(쇼핑)+5(관광)+7(기타)** 월별 일평균이다.

`y[d,m] = 해당 월 도착 이동 추정량(목적 4+5+7)의 일별 합 / 유효 관측 일수`

이 값은 관광객 수나 실제 상권 방문자 수가 아니라 **비정기 목적 이동의 대리 지표**다. 목적 7의 범위가 넓으므로 `4+5`만의 규모와 주 결과 민감도를 별도 제시한다. 동 규모가 큰 순위와 새로 뜨는 동 순위는 구별한다. ‘뜨는 동’은 예측 `y`의 전년 동월 대비 변화 또는 사전에 고정한 계절 기준선 대비 초과분으로 정하고 최소 이동량 조건을 둔다.

## 2. 실제 학습 표의 열

아래 `lag2`는 대상 월 `m`의 두 달 전 관측값을 뜻한다. **실제 첫 공개 날짜가 더 늦으면 시차를 늘려야 한다.** 모든 원자료에는 관측 월, 첫 공개/수정 날짜, 다운로드 버전을 기록한다.

| 원자료 | 만드는 열 예시 | 모델에서의 역할 | 결합·주의 |
|---|---|---|---|
| 수도권 생활이동 목적별 내국인 | `y`, `y_lag2`, `y_lag3`, `y_lag12`, 최근 3개월 평균·전년 동월비 | `y`가 유일한 주 GT. 과거 `y`가 핵심 학습 정보 | 도착 행정동 8자리 코드로 일·목적을 월 단위 집계. ARIMA 계열에는 시계열 `y` 자체를 넣고 시차표는 기준선·EDA·추후 전역 모델에 사용. 예측 월의 `y`는 입력 금지. |
| 재현의 이름표 ZIP `01`·`02`·`04` | 코드, 동명, 검색어 묶음, 연결 가중치 | 공간 결합표. 검색할 장소명 정의 | 427개 현재 동 목록을 시간별 공식 코드와 대조. 2025년 이후 생긴 동의 과거 `y`를 임의로 나누지 않음. 여러 동에 걸친 검색어는 실제 방문을 배분한 수치로 해석하지 않음. |
| 재현의 네이버 검색 시계열 | `search_level_lag2`, `search_change3_lag2` 중 우선 하나 | 핵심 후보 외생변수 X: 사전 관심 | 이름표 `02`·`04`로 검색어 묶음을 동에 가중 합산. 566개 묶음 전체를 모델에 넣지 않음. PDF상 422동이므로 나머지 5동은 결측 표시. 네이버 값은 절대 건수가 아닌 상대 지수이며 조회 기간을 늘리면 척도가 바뀔 수 있어 기준 시점을 고정·기록. |
| 음식점 인허가 원자료(재현 팀 자료) | `food_stock_lag2`, `food_net_rate_3m_lag2` 또는 `food_open_3m_lag2` | 후보 X: 상권 공급·변화 | 점포 좌표→당시 행정동, 일반·휴게음식점 범위 고정. 개업일·폐업일 기준으로 월 집계. 일괄 폐업·재등록은 별도 플래그와 민감도 분석. 폐업 기록의 공개·수정 지연 점검. |
| 지하철 역별 하차 인원 | `station_exit_lag2`, `station_exit_change3_lag2` 중 하나 | 후보 X: 접근·활동 신호 | 역×일을 월 일평균으로 만든 뒤 이름표 `05`의 1km 역 연결 가중치로 동에 집계. 한 역이 여러 동에 반영됨을 명시. 2023~2025 현재 저장소 원자료가 있고 2026 구간은 추가 수집 필요. 당시 없던 역은 과거에 넣지 않음. |
| 행정동 서울 생활인구 | `living_day_lag2` | **보조 실험 X**, 주 모델의 필수 입력에서는 제외 | 11~21시 동별 월 평균. 생활이동과 유사한 통신 기반 신호여서 증분 효과를 동일 평가 행에서 시험. 행정동 자료 생산은 2026-07 종료되어 이후 달에는 동일 방식으로 지속 사용 불가. |
| 달력 | 대상 월의 주말·공휴일 수, 월 | 사전에 확정 가능한 X | 목표 월의 달력은 미래 정보 누출이 아님. 일평균 목표값이어도 요일 구성 차이가 남음. |
| 상권분석서비스 길단위인구·점포·매출 | 우선 학습 열 없음 | 보조 설명·외부 타당성 확인 | 분기 단위, 공간 단위·배포 변경, 발표 지연을 먼저 점검. 음식점 **인허가 원자료**와 상권분석서비스 점포 수를 같은 자료로 혼동하지 않음. |
| S-DoT 등 장소 센서 | 학습 열 없음 | 제한적 외부 확인 | 센서 장소·기간이 맞을 때만 실제 활동 변화 방향을 비교. |

재현의 리포트는 검색 2022-01~2026-10(422동), 인허가 2015-01~2026-10(427동)이라고 보고한다. 현재 이 작업 폴더에는 그 **행정동×월 원시 시계열 표**가 없으므로, 실제 결합 전 팀에서 CSV와 산출 코드·버전을 받아야 한다. 리포트에 제시된 검색/개폐업 자체의 예측 성능은 생활이동 예측 성능이 아니다.

## 3. 예측 시점 예시와 누출 방지

예를 들어 **2026년 6월 1일에 6월을 예측**한다면, 보수적 실험에서는 생활이동과 모든 동적 보조 지표를 **2026년 4월분까지** 사용한다. 목표 열은 2026년 6월 `y`이고 학습 입력에는 나타나지 않는다. 검색이나 지하철 5월분이 실제로 6월 1일 이전 공개되었다는 기록이 있으면 별도의 ‘빠른 정보’ 실험에서만 `lag1`을 사용한다.

ARIMAX/SARIMAX에서는 모형이 목표 월 `m`에 요구하는 외생변수 열을 `X_m := 원자료 X_(m-2)`로 미리 이동시킨다. 그러면 `m-2`까지 관측한 상태에서 2개월 앞 예측에 필요한 `X_(m-1)`, `X_m`은 각각 원자료 `m-3`, `m-2`여서 미래 X를 따로 예측할 필요가 없다. 이 정렬을 코드에서 검증해야 한다.

네이버 API의 `ratio`는 요청 구간 내 최댓값 100으로 표준화된다. 2026년까지 한 번에 조회한 지수로 2024년 예측을 검증하면 과거 당시의 척도와 달라질 수 있다. 각 fold의 학습 종료일 기준으로 조회/정규화를 재현하거나, 고정 앵커가 있는 산출 방식과 원본 요청 내역을 확인한다.

## 4. 모델 실험 순서

| 단계 | 모형 | 입력 | 답할 질문 |
|---|---|---|---|
| B0 | `y_(m-2)` 단순 기준선, 가능하면 전년 동월 기준선 | 과거 생활이동 | 어려운 모형이 필요한가? |
| M1 | ARIMA | 동별 과거 생활이동 | 추세가 도움이 되는가? |
| M2 | SARIMA | 동별 과거 생활이동 + 계절항 | 월별 계절성이 도움이 되는가? |
| M3a | ARIMAX | 생활이동 + **검색 요약 1개** | 사전 관심이 예측력을 더하는가? |
| M4a | SARIMAX | 생활이동 + **같은 검색 요약 1개** | 계절성을 고려해도 효과가 남는가? |
| M3b/M4b | ARIMAX/SARIMAX | 검색 대신 음식점 변화 1개, 역 하차 1개, 생활인구 1개를 **각각** | 어떤 보조 자료가 도움이 되는가? |
| M3c/M4c | ARIMAX/SARIMAX | 검증에서 효과가 확인된 변수 1~2개 | 함께 쓸 때도 좋아지는가? |

모든 단계에서 **동일한 동·월·예측 거리**로 비교한다. 검색 결측 5동 때문에 표본이 줄면 검색을 넣지 않은 모델도 같은 422동·월로 다시 평가한다. 동별 월 이력이 약 24~46개이므로 계절 SARIMA와 다변량 SARIMAX의 차수는 단순하게 고정하고 실패·수렴 여부를 함께 보고한다. 최종 발표에 4개 모형만 요구되면 M1·M2·M3a·M4a를 주 표로, B0를 필수 기준선으로 둔다.

## 5. 학습·검증·최종 시험

현재 공개 페이지에는 생활이동 목적별 내국인 파일이 **2023-01~2026-10** 있다. 아래는 **품질 점검을 통과한다는 조건의** 시간순 설계다.

| 구간 | 제안 | 용도 |
|---|---|---|
| 학습 시작 | 2023-01~2024-12 | 고정 차수·단순 모델의 최초 적합. 계절 모형에 24개월은 짧으므로 결과는 보수적으로 해석. |
| 개발 검증 | 2025-01~08 | 외생변수 선택, 차수·변환 선택. 매월 실제 이용 가능한 시차만 사용한 rolling-origin 평가. |
| 품질 점검 | 2024-08~10 급증, 2025-09 이후 원천 차이 | 공개 원본의 구조적 변화·누락·재배포를 확인. 원인을 모르면 구간별 성능을 분리하고 최종 확정 주장 보류. |
| 최종 시험 후보 | 2026-01~10 | 검증에서 선택한 규칙을 고정한 뒤 한 번 평가. 2025-09 이후 생활이동의 품질과 2026년 공개 버전이 확인되어야 공정한 연속 시계열 시험이 가능. |

실제 운영 모의에서는 월 `m`의 1일을 origin으로 하고 자료 공개일을 재현한다. `m-2`까지 이용 가능한 `y`로 2개월 앞을 예측한다. 다만 현재 내려받는 2023~2025 파일 중 일부는 후일 재배포본이므로, 과거에 그 값이 *실제로 공개되어 있었는지*는 별도 확인해야 한다. 이를 못 하면 ‘현재 배포본을 사용한 회고적 백테스트’라고 명시한다.

주 지표는 전체 WAPE와 MAE, 보조로 동별 오차 분포와 **사전에 정의한 상승 상위 K개 동 적중률**을 둔다. 전체 WAPE는 큰 동에 치우치므로, 동별 결과를 같이 보고한다. 2025년 용신동 분리로 생긴 두 동 등 과거 개별 시계열이 없는 경우 `not_estimable`로 표시한다.

## 6. 자료별 준비 우선순위

1. **P0:** 2023~2026 생활이동 목적별 월 집계와 월별 공식 동 코드, 품질·배포 이력. 이것만으로 기준선·ARIMA·SARIMA 가능.
2. **P1:** 재현의 `행정동 코드×월` 검색 지수/검색 비중 표와 음식점 개업·폐업·영업 점포 표, 산출 코드와 조회 기준. 이를 받아 ARIMAX·SARIMAX 증분 실험.
3. **P2:** 2026 역 하차량과 역사 변경 이력. 접근 신호 실험.
4. **보조 실험:** 2026-07까지의 행정동 생활인구. 동일 기간으로만 모델 비교. 분기 상권 자료와 현장 센서는 설명·외부 확인 우선.
