# 427개 행정동 프로젝트 파이프라인

작성일: 2026-11-12 · 상태: 중간발표용 설계 및 데이터 품질 확인 중

> **갱신:** 아래 학습·검증 표는 당시 수집한 2023~2025 파일만 대상으로 한 파일럿 설계다. 공식 생활이동 페이지에서 2026-10까지의 파일을 확인했으므로, 전체 학습 데이터·최종 시험 설계는 [MODEL_DATA_DESIGN_2026.md](MODEL_DATA_DESIGN_2026.md)를 따른다. 행정동 생활인구는 2026-07 이후 생산이 종료되어 장기 운영의 필수 변수로 두지 않는다.

## 1. 한 문장으로

**월초에 확인 가능한 과거 정보로 서울 행정동의 해당 월 `4+5+7` 목적 도착 이동량을 예측한다.** 생활인구·검색량·역 하차량·상권 자료는 이 목표값을 예측하는 **입력 변수(feature)**다. 이 자료들 자체를 각각 예측해서 합치는 설계가 아니다.

```
과거 생활이동 y ───────────────────┐
과거 생활인구 ─────────────────────┤
과거 네이버 지역 검색지수 ──────────┼─> ARIMA 계열 비교 ─> 해당 월 행정동별 y 예측
과거 주변 역 하차량 ────────────────┤
공개된 과거 상권·점포 자료 ──────────┘
                 ↑
       재현의 행정동 이름표·역·상권 연결표로 공간 단위 통일
```

## 2. 무엇이 정답이고 무엇이 feature인가

| 자료 | 원래 단위 | 프로젝트 역할 | 행정동·월로 만드는 방법 | 월 `m` 초의 허용 범위 |
|---|---|---|---|---|
| 수도권 생활이동 목적별 내국인 | 도착 행정동 × 일·시간·목적 | **유일한 주 정답값 `y`** + 자기 자신의 과거값 | 목적 4(쇼핑)+5(관광)+7(기타)를 월 유효 일수로 나눈 일평균 | 입력으로는 보수적으로 `m-2`까지 |
| 서울 생활인구 | 행정동 × 일·시간 | 외생변수 `X` | 11~21시 평균 등 동별 월 요약 | `m-2`까지 |
| 네이버 검색 트렌드 | 검색어 묶음 × 월 | 후보 외생변수 `X` | 이름표 `02`·`04`의 검색어 묶음과 가중치로 동네·역·권역 신호 생성 | `m-1`까지, API 척도 고정 필요 |
| 지하철 역 승하차 | 역 × 일 | 후보 외생변수 `X` | 이름표 `05`의 1km 면적 비율로 주변 역 하차 추세를 연결 | 공개 확인 시점까지, 첫 실험은 `m-2` |
| 상권 유동·점포·음식점 | 상권 × 분기 또는 점포 × 일 | 후보 외생변수 `X` | 이름표 `06`의 상권–동 겹침과 시점별 영업 상태로 집계 | 공개된 과거 분기·월만 |
| S-DoT 등 현장 센서 | 센서 지점 × 시간 | **외부 타당성 확인** | 실제 센서가 해당 장소와 기간에 부합하는 경우만 비교 | 모델의 주 정답값으로 섞지 않음 |

이름표 ZIP은 **시간에 따른 이동량이나 검색량이 아니라 공간 연결 규칙**이다. `01`은 427개 동 목록, `04`는 동–이름 연결과 가중치, `02`는 검색어 묶음, `05`는 주변 역, `06`은 상권 연결표다. 월별 자료에 이름이 아니라 **8자리 행정동 코드**로 결합한다. 검색어는 여러 동에 연결될 수 있으므로 이름표 연결을 개인별 실제 방문으로 해석하지 않는다.

재현의 2026-11-12 리포트에는 **2022-01~2026-10 월별 네이버 검색 비중(422개 동)**과 **2015-01~2026-10 음식점 인허가 자료(427개 동)**가 있다고 적혀 있다. 따라서 API 키가 없더라도 팀원이 만든 월별 결과를 공유받으면 사용할 수 있다. 다만 현재 이 작업 폴더에는 그 원본 시계열이 없어서 지금 만드는 ARIMAX/SARIMAX의 `X`는 2개월 전 생활인구이며, 검색·음식점 지표의 생활이동 예측 효과는 아직 검증하지 않았다. 공유받은 뒤 `기본 ARIMA → +검색 → +역 → +음식점` 순서로, **같은 동·월 평가 행**에서 증분 효과를 비교한다. 짧은 동별 이력에 566개 검색어를 직접 넣지 않고 이름표 가중치로 동별 소수의 합성 신호를 만든다. 검색 지표는 서울 합계 대비 상대 비중이므로 검색 건수나 방문자 수로 해석하지 않는다.

## 3. 목표값의 의미

`y(d,m) = 동 d에 도착한 목적 4+5+7의 월 합계 / 유효 관측일수`

이는 **행정동 단위 비정기 목적 도착 이동량의 대리 지표**다. 이동의 목적은 통신 기반 추정 분류이며, `기타(7)`에 여가·상권 방문이 포함될 가능성과 다른 미분류 이동이 섞일 가능성이 함께 있다. 40개 동 파일럿에서 4+5는 목표값의 약 2.3%였으므로, 주 결과와 함께 4+5 단독 결과·기타 비중을 보고한다. ‘핫플 방문자 수’라는 직접 측정값으로 부르지 않는다. ## 4. 427개 동과 과거 행정동 코드

이름표는 **2025-12-31 기준 427개 동**이다. 공식 월별 코드 자료에서는 2025년 8월에 `용신동(11230536)`이 `신설동(11230515)`과 `용두동(11230533)`으로 분리된다. 따라서 새 두 동에는 그 전 월의 개별 정답값이 없다. 두 동에 용신동 전체 값을 복사하거나 임의 비율로 나누면 안 된다. 2023년 1월 `일원2동`에서 2023년 2월 `개포3동`으로 바뀐 코드도 관측 시점을 명시한다. 현재 모형 학습 시작을 2023년 3월로 둔 이유 중 하나다.

출력은 **427개 동 × 36개월의 패널**을 만들되, 해당 코드가 아직 없던 월은 `not_yet_created`로 둔다. 네 모형의 2025년 12개월 비교는 역사가 충분한 동만 포함한다. 새 두 동은 결과표에 `not_estimable`과 사유를 남긴다. 이것이 ‘427개 동 전체 연결’과 ‘427개 동 모두에서 동일한 3년 모델 평가’의 차이다.

## 5. 예측 시점과 입력 누출 방지

매월 1일에 그 달 `m`의 이동량을 예측한다. 생활이동과 생활인구는 실제 공개일을 최종 확인하기 전까지 `m-2`까지 사용한다. 따라서 ARIMA 계열도 마지막으로 아는 `y(m-2)`에서 **2개월 앞 예측**을 한다. `m-1` 정답값을 이미 안다고 놓고 1개월 앞 예측하면 이 실험의 조건과 맞지 않는다.

네이버는 2022년 사전 기간에 검색어 확인·저빈도 제외 규칙을 고정하고, 상대지수의 요청 간 척도와 미래 조회기간 재척도 문제를 해결한 뒤 투입한다. 역·상권 연결표의 2025~2026년 기준 공간 정보가 2023년 당시에도 유효했는지 확인해야 한다. 당시 없던 역이나 뒤에 생긴 권역 명칭을 과거 시점 feature로 넣지 않는다.

## 6. 네 모형의 관계

| 모델 | 입력 | 현재 고정 차수 예시 |
|---|---|---|
| ARIMA | 과거 `y` | (1,1,0) |
| SARIMA | 과거 `y` + 12개월 계절항 | (1,1,0)×(1,0,0,12) |
| ARIMAX | 과거 `y` + 과거 생활인구 `X` | (1,1,0) + `X` |
| SARIMAX | 과거 `y` + 계절항 + `X` | (1,1,0)×(1,0,0,12) + `X` |

네 모형은 **동일한 한 개의 `y`를 예측**한다. `X` 후보가 늘어나면 한 번에 모두 넣지 않고 `+검색`, `+역`, `+상권`을 차례로 비교한다. 인구나 검색량의 미래값을 따로 예측해서 사용하지 않는다. 목표 월에 필요한 과거 시차값만 사용한다.

## 7. 학습·검증·시험

**현재 2023~2025 자료에는 깨끗하게 분리된 장기 학습·검증·시험 구간이 부족하다.** 2024년 8~10월에는 현재 서울시 배포 원본에도 있는 광범위한 급증이 있으나 원인이 미확인이다. 서울시는 2025년 9월 이후 원천데이터 차이를 공지했다. [EDA 검토](EDA_REVIEW_2026-11-11.md), [서울시 품질 공지](https://data.seoul.go.kr/together/notice/datasetNoticeView.do?bbsCd=10008&ditcCd=&pageIndex=1&seq=8e761caf2ef8f864e8b79951c3fa74c2)

| 단계 | 기간 | 지금의 처리 |
|---|---|---|
| 학습 | 2023-03~2024-11 | 현 4모형의 고정 차수 적합. 2024-08~10 급증 포함 → 수치 잠정 |
| 검증 | 현재 **신뢰 가능한 독립 기간 미확정** | 이상 구간 원인 확인 후 차수·feature 선택용 기간을 고정. 그전에는 2025 시험 성능을 보고 차수를 반복 조정하지 않음 |
| 시험 | 2025-01~2025-08를 우선 보고, 2025-09~12 별도 | 매월 `m-2`까지로 2개월 앞 예측. 동·월별 MAE·WAPE·상위 상승 후보 순위 평가 |

중간발표에서는 **“고정 차수의 파일럿 백테스트”**라고 표현한다. 이를 완성된 train/validation/test 최종 성능이라고 부르지 않는다. 품질 확인 후 가능한 선택지는 `2023-01~2024-06 학습 / 2024-07~12 검증 / 2025-01~08 시험`이지만, 2024년 검증 구간의 급증을 설명하지 못하면 이 분할로 모델을 선택하기 어렵다. 12개월 계절 모형에는 18~21개월 학습 이력도 짧다.

## 8. 성공 조건과 발표 주장

- 수치 예측: 동일한 동·월에서 `m-2` 반복 기준선 대비 MAE와 WAPE 개선. 규모가 큰 동이 전체 WAPE를 지배할 수 있으므로 동별 오차도 보고한다.
- 후보 순위: 사전에 정한 상승 기준과 최소 유입량으로 상위 K곳 적중률을 평가. 급증 구간의 전년 대비 비교는 원인 확인 전까지 주 결과에 사용하지 않는다.
- 외생변수 효과: `X`를 추가한 모델이 **동일 평가 행**에서 대응하는 단변량 모델보다 나아야 한다. 성능이 나쁘면 그대로 보고한다.
- 주장 범위: “행정동의 목적 4+5+7 도착 이동량을 과거 자료로 예측했고, 검색·교통·상권 신호의 추가 효과를 순서대로 검증했다.” 검색값 수집 전에는 검색 효과를 검증했다고 주장하지 않는다.
