# 재현의 검색·음식점 예측 리포트와 생활이동 GT 설계 검토

작성일: 2026-11-12 · 검토 대상: `서울 행정동 검색량·음식점 개폐업 시계열 예측 결과 리포트.pdf` (17쪽)

## 결론

프로젝트의 질문을 **“다음 달 어느 행정동의 비정기 목적 도착 이동량이 증가할까?”**로 정한다면, 생활이동 목적 4+5+7의 동별 월별 값이 유일한 주 목표값 `y`이다. 학습 시 가장 중요한 입력도 같은 생활이동의 과거값 `y` 시차·추세·계절성이다. 검색 비중, 음식점 개폐업, 생활인구, 역 승하차는 **시점에 맞춰 관측된 과거값을 넣는 보조 변수 `X`**다. 모든 자료를 각각 예측한 뒤 섞는 구조는 기본 설계가 아니다.

```
예측 시점 t에 이미 공개된 생활이동 y(≤t) ───┐
같은 시점에 이미 공개된 검색·점포·생활인구 X ─┼─> 동별 생활이동 y(t+h) 예측
달력·행정동·공간 연결표 ────────────────────────┘
```

## 첨부 리포트에서 확인한 것

| 항목 | 리포트의 설계 | 생활이동 프로젝트에서의 해석 |
|---|---|---|
| 목표값 | 검색 비중, 음식점 개업 수, 폐업 수, 순증률을 각각 예측 | 생활이동을 예측한 결과는 아니다. 이 네 지표는 우리 주 목표의 후보 입력이다. |
| 공간·기간 | 검색 422개 동(2022-01~2026-10), 음식점 427개 동(2015-01~2026-10) | 생활이동 427동 패널에 붙일 수 있는 자료가 팀에 있다는 근거다. 검색 결측 5개 동은 별도 처리한다. |
| 교차 변수 | 검색 예측에 음식점, 음식점 예측에 검색을 추가했으나 3개월 예측의 성능 개선이 거의 없음 | `검색 → 생활이동`, `개폐업 → 생활이동`의 예측 효과는 아직 실험하지 않았다. |
| 평가 | F2024·F2025 개발 fold. 2026-01~09 최종 시험은 미실행 | 보고된 오차·유의확률은 생활이동 모델의 시험 성능으로 인용할 수 없다. |
| 검색 척도 | 네이버 상대 지수를 서울 합계 대비 비중으로 사용 | 검색 *건수*나 실제 방문객 수로 읽으면 안 된다. |
| 음식점 자료 | 전체 포함 업종 664,496개 중 622,857개(93.7%)를 동에 매핑. 일괄 폐업·재등록을 점검 | `개업`, `폐업`, `영업 점포 수` 등을 분리하고 행정 재등록 효과를 살펴야 한다. |

리포트의 “핫스팟” 목록은 **검색·점포 기준의 현황 또는 자체 목표 예측**이다. 생활이동 GT로 검증한 핫스팟이라고 발표하면 연구 질문과 근거가 어긋난다. 리포트 자체도 목록의 일부가 예측이 아닌 현황이라고 밝힌다.

## 모델과 평가를 한 줄로 맞추는 방법

1. **목표 고정:** 동 `d`, 월 `m`에 도착한 목적 4+5+7 이동의 일평균 `y(d,m)`을 GT로 둔다. 목적 7은 범위가 넓으므로 4+5만의 보조 분석도 보고한다.
2. **기준선:** 마지막 관측값, 작년 같은 달, 과거 생활이동만 쓴 ARIMA·SARIMA를 먼저 평가한다.
3. **보조 지표의 증분:** 같은 예측 시점·같은 평가 동·월에서 `생활이동만`과 `생활이동+검색`, `+음식점`, `+생활인구`를 비교한다. ARIMAX·SARIMAX에는 필요한 소수의 관측 시차 변수만 넣는다. 36개월 이력에 수백 개 검색어를 넣지 않는다.
4. **누출 방지:** 예측 기준일에 공개되어 있던 값만 사용한다. 2026년 인허가·검색 값을 2025년 예측의 입력에 넣지 않는다. 네이버 상대지수의 재조회·정규화 기준도 학습 시점으로 고정한다.
5. **검증:** 시간순 개발 fold에서 변수·차수를 결정하고, 마지막 기간은 한 번만 시험한다. 현재 2023~2025 생활이동에는 2024-08~10 급증과 2025-09 이후 품질 이슈가 있어 안정적인 검증 구간을 먼저 확정해야 한다. 2026년 검색·음식점 자료가 있어도 같은 시기의 생활이동 GT가 없으면 생활이동 모델의 최종 시험은 못 한다.
